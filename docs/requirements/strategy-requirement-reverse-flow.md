# 策略需求反向追溯与正向验证业务流

## 1. 定位

- `已确认` 策略可以作为数据与因子需求的入口，但单一策略不得直接定义全局数据层。
- `已确认` 需求按“策略业务意图 -> 特征与字段契约 -> 因子候选 -> 原始事实与授权”逆向追溯。
- `已确认` 资产按“原始事实 -> 标准数据 -> 因子制品 -> 数据集绑定 -> 新策略版本”正向建设。
- `已确认` 历史策略版本保持不可变；需求完善和语义修正通过新版本交付。

本业务流补充 `docs/requirements/business-flow.md`，用于策略驱动的数据、因子和运行时改造，不替代数据中心与因子研究既有主流程。

## 2. 主流程

1. 冻结策略 ID、版本、源码哈希、参数、股票池、复权、成本和执行时点。
2. 对照业务意图、依赖声明和源码实际访问，形成策略需求清单与差距矩阵。
3. 将需求分为原始事实、可复用因子、股票池规则、策略信号、风险规则和执行规则，不把所有中间变量都提升为因子。
4. 数据中心核验来源授权、字段、共同覆盖窗口、点时可得性、质量状态和预热长度；不满足时生成数据缺口，不启动回测。
5. 因子研究验证候选特征的覆盖、IC/Rank IC、稳定性、衰减、换手、成本和样本外表现；通过后发布不可变制品。
6. 新策略版本显式绑定数据集、数据版本和精确因子制品，执行声明与实际访问一致性校验。
7. 按“黄金样本 -> 单品种 -> 小股票池独立账户 -> 全市场独立账户 -> 共享资金组合 -> 样本外/滚动验证”正向重放。
8. 报告中心根据预先冻结的验收阈值给出“采用 / 继续研究 / 否决”建议，最终决策仍由人工确认。

## 3. 强制门禁

### 数据门禁

- 所有必需数据集的共同覆盖期必须包含预热区间和评价区间。
- 数据来源必须有明确授权边界；缺失、未授权或存在阻断质量问题时失败关闭。
- 证券状态、行业、指数成分、公司行为和因子值必须按点时可得性绑定。

### 因子门禁

- 定义、方向、窗口、输入字段、点时规则和制品哈希必须冻结。
- 代理指标必须使用代理名称并披露与目标语义的差异。
- 因子须完成黄金样本、无前视、稳定性和样本外验证后才能发布制品。

### 策略门禁

- 零未声明依赖、零无解释冗余依赖。
- 参数 Schema、预热长度、信号时间和执行时间完整。
- 策略执行确定，并通过故意读取未来数据的负向测试。

### 回测门禁

- 开发区间与封存样本外区间隔离。
- 费用、滑点、T+1、停牌和涨跌停口径必须披露。
- 三类回测使用同一策略版本、数据版本和因子制品证据。

### 决策门禁

- 研究目标和验收阈值在读取封存样本外结果前冻结。
- 历史评分和回测收益只作为证据，不构成未来收益保证或实盘上线判断。

## 4. 状态流转

- 需求：`draft -> reviewed -> confirmed -> superseded`。
- 数据缺口：`identified -> authorized -> implementing -> verified/blocked`。
- 因子候选：`proposed -> researching -> rejected/ready_artifact`。
- 策略候选：`draft -> validated -> backtesting -> needs_review/adopted/rejected`。
- 发布：只有数据、因子、策略、回测和人工决策门禁同时满足，才能进入下一阶段候选基线。
