# 数据集契约与模块适配设计

状态：M0 设计基线，已确认，待后续实现持久化与 UI 接入。

## 1. 目标

以统一的数据集对象连接数据中心、因子库、策略编辑和三种策略回测模式。数据集定义描述数据能力，数据集版本描述已发布快照，数据集订阅描述消费者需要的数据切片，回测输入包冻结一次回测实际使用的全部数据与代码绑定。

## 2. 四层对象

1. `DatasetDefinition`：数据集身份、字段 Schema、频率、来源、质量和 point-in-time 契约。
2. `DatasetVersion`：覆盖范围、质量报告、来源任务、内容 Hash 和发布状态。正式回测只允许 `published`。
3. `DatasetSubscription`：标的、日期、字段、复权、观察时点、最小历史窗口和缺失处理策略。
4. `BacktestInputBundle`：数据集版本、订阅、策略版本、源代码 Hash、因子绑定和股票池快照的可复现绑定。

## 3. 适配边界

- 数据中心继续负责生产、质量检查和发布数据版本；现有 `DATASET_CATALOG` 作为目录初始来源。
- 因子定义增加数据依赖、字段需求和 point-in-time 规则；因子结果记录输入数据版本。
- 策略编辑器增加数据需求和因子依赖校验；现有策略编辑页面保留为备用入口，不删除、不覆盖、不改变现有 `target-weights-v1` 契约。
- 回测创建时生成输入包；单品种、独立账户批量、共享现金组合三种模式继续保持各自的资金和统计语义。
- 报告展示数据集版本、覆盖范围、因子版本、策略 Hash 和质量证据。

## 4. 首期数据范围

首期只接入项目已有治理范围：A 股日线、指数日线与沪深 300、证券目录、交易日历、交易状态、公司行动、历史行业分类、行业/概念板块和事件数据。财务报表、付费数据、海外数据和独立因子研究流水线不纳入本期。

## 5. 不变量

- 不读取未发布数据执行正式回测。
- 不允许消费者静默使用未声明的数据集或字段。
- 不使用当前分类回填历史分类。
- 数据缺失、版本缺失或 point-in-time 不满足时返回明确不可用原因。
- 输入包创建后不可被后续数据发布覆盖。

## 6. 实施顺序

M0：契约模型与文档；M1：数据中心目录和版本查询；M2：因子依赖与结果溯源；M3：策略编辑器校验；M4：回测输入包与报告接入；M5：策略目录展示样本内外表现。
