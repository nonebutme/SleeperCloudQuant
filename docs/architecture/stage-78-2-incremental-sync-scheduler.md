# 阶段 78.2：增量同步与应用内调度状态机

## 1. 阶段结论

`已确认`：阶段 78.2 已完成。规范 A 股数据库已新增持久化增量队列和调度状态机，应用内盘后调度设置已启用。

- 调度时区：`Asia/Shanghai`
- 调度时间：每天 `18:15`
- 同步口径：`raw/qfq/hfq`
- 全局上游请求上限：每分钟 60 次请求尝试
- 最大并发工作数：4
- 单项最大尝试次数：3
- Windows 任务计划：未修改

调度设置保存在规范数据库。应用进程运行时启动后台 tick；应用未运行时不会自行唤醒操作系统。

## 2. 新增持久化实体

- `market_incremental_sync_jobs`
  - 保存手动、定时和启动补偿任务。
  - 状态包括 `queued/running/validating/published/partial_failure/failed/interrupted/completed_noop`。
  - 记录目标交易日、任务数、成功数、隔离数、写入量、质量报告和数据版本。
- `market_incremental_sync_items`
  - 按 `job + symbol + adjustment` 保存断点。
  - 状态包括 `pending/running/retry_wait/completed/quarantined`。
  - 保存尝试次数、下次尝试时间、错误、接收量和写入量。
- `market_scheduler_settings`
  - 保存启用状态、时区、盘后时间、复权口径、限频、并发、重试和最近调度信息。
- `market_schema_migrations`
  - 新增 `78.2.0` 迁移记录。

## 3. 运行流程

1. 到达盘后时间后，先检查当天是否已经调度。
2. 刷新证券目录；同一天已刷新时不重复请求。
3. 增量刷新交易日历。
4. 根据最新开市日确定目标交易日。
5. 增量刷新沪深 300 正式基准。
6. 基准尚未覆盖目标日时返回 `data_not_ready`，不启动全市场价格任务。
7. 为落后目标日的标的和复权口径生成持久化工作项。
8. 工作线程共享一个全局请求限频门。
9. 瞬时错误按指数退避重试；超过上限后单项进入 `quarantined`，其他项目继续。
10. 所有工作项完成后执行发布级质量门禁。
11. 质量通过后，在一个数据库事务中切换 `published` 数据版本；失败时保留旧正式版本。

## 4. 恢复与幂等

- 应用启动时把遗留的 `running/validating/retry_wait` 工作恢复到持久队列，不立即绕过限频访问外部数据源。
- 同一自然日使用唯一 `schedule_key`，避免重复创建定时任务。
- 若崩溃发生在“记录已调度、尚未执行”之间，下次 tick 会继续原任务。
- `published` 和 `completed_noop` 任务不会重复执行。
- `quarantined` 项必须通过明确的重试动作重新入队。
- 重发同一版本清单不会把版本自身设为父版本，也不会先错误地标记为 `superseded`。

## 5. 质量与版本门禁

发布前检查：

- 工作项全部完成且没有隔离项。
- 每个请求项在目标交易日存在对应行情。
- 日线自然主键重复组为 0。
- raw OHLCV 结构有效。
- 目标日期是正式交易日历中的开市日。
- 沪深 300 正式基准已覆盖目标日。

新版本成员会重新计算：

- raw/qfq/hfq 行情行数、标的数、起止日期和内容摘要。
- 交易日历行数、起止日期和内容摘要。
- 沪深 300 行数、起止日期和内容摘要。

未在本阶段全市场刷新的生命周期、状态、公司行动和复权因子证据沿用上一正式版本的成员摘要，不伪造增量。

## 9. 多日停牌零行增量修复（2026-08-12）

- 根因：增量工作项保留上一覆盖边界至目标日的多日区间；旧逻辑仅直接接受单日目标停牌的零行结果。已有全窗口停牌证据时，历史推断不会新增记录，导致多日零行被重复隔离。
- 新规则：多日零行只有在以下证据同时成立时才完成：窗口首个开放交易日明确停牌、目标交易日明确停牌、窗口内 raw/qfq/hfq 任一口径均无行情。
- 明确边界：若窗口内任何口径存在行情，零行口径仍保持隔离，避免把单一复权口径缺数误判为停牌。
- 完成证据：工作项写入 completion_reason=suspended_increment_window_without_any_prices；不人工构造 OHLCV，不绕过发布级质量门禁。
- 现有任务恢复：对 partial_failure 任务执行“仅重试失败项”，再显式“运行任务”；质量通过后沿用原子发布，新任务无需重建。
