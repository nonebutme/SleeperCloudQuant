# web-app 批次 1 具体任务清单（页面 A 静态壳层 + 最小联调入口）
时间：`2026-07-06`

## 一、文档定位

- `已确认`：本文档用于定义 `web-app` 首批实现中的批次 1 具体任务清单。
- `已确认`：批次 1 只围绕“页面 A：市场数据查询页 + 最小页面壳层 + 最小联调入口”展开。
- `已确认`：本文档用于后续正式实现前的任务收束，不直接扩展到页面 D、页面 C 或页面 B。

## 二、批次 1 目标

批次 1 的唯一目标是：

- 建立一个最小可运行的 PC Web 静态壳层
- 完成页面 A 的最小查询表单、结果展示区与错误提示区
- 打通页面到 `market` 读取类接口的首条联调路径

更具体地说，批次 1 只需要回答两个问题：

1. 当前项目能否先跑起一个最小 Web 访问壳层
2. 页面 A 能否在不扩后端能力面的前提下，稳定查询并展示市场数据结果

## 三、批次 1 任务清单

### 3.1 任务 1：建立最小前端目录与静态壳层

建议任务：

- 新建最小前端目录结构
- 提供一个可直接本地运行或被最小静态服务承载的页面入口
- 建立极简导航壳层，但导航只点亮页面 A，其他页面先保留占位或禁用态

本任务完成标准：

- 页面能被浏览器打开
- 页面有统一标题区 / 导航区 / 内容区
- 不需要完整工程化脚手架也能先运行

当前不做：

- 复杂前端工程体系
- 组件库建设
- 主题系统
- 页面 D / C / B 的真实内容实现

### 3.2 任务 2：定义页面 A 的最小表单结构

建议任务：

- 为价格历史查询准备最小输入项：`symbol`、`start_date`、`end_date`
- 为交易日历查询准备最小输入项：`start_date`、`end_date`
- 为同步状态查看准备最小入口：`dataset`

本任务完成标准：

- 页面 A 能分出三块最小功能区：
  - 价格历史查询
  - 交易日历查询
  - 同步状态查看
- 每块功能区都只有最小必需输入项

当前不做：

- 批量 symbol 输入
- 复杂筛选器
- 多市场切换
- 高级参数面板

### 3.3 任务 3：定义页面 A 的最小结果展示结构

建议任务：

- 为价格历史结果准备最小表格区或列表区
- 为交易日历结果准备最小列表区
- 为同步状态准备最小对象展示区
- 为请求失败准备统一最小错误提示区

本任务完成标准：

- 查询成功时，用户能直观看到返回结果
- 查询失败时，用户能看到最小错误信息
- 空结果时，页面能保持稳定，不出现结构性错乱

当前不做：

- 图表可视化
- 卡片式分析面板
- 多结果对比区
- 页面级缓存与历史记录

### 3.4 任务 4：打通页面 A 与后端最小联调入口

建议任务：

- 直接对接当前已有 `market` 相关接口
- 明确页面请求方式、返回结构映射与最小错误语义处理
- 保持页面只消费当前已有接口，不新增页面专用后端接口

建议优先联调接口：

1. `GET /api/market/price-history`
2. `GET /api/market/trading-calendar`
3. `GET /api/market/sync-status/{dataset}`

本任务完成标准：

- 页面 A 能完成至少一条真实查询路径
- 其余两条路径至少完成结构接通与最小展示约定
- 页面层不要求改写后端返回契约

当前不做：

- 新增 route
- 新增聚合接口
- 页面专用响应包装
- market 同步逻辑扩面

### 3.5 任务 5：定义批次 1 的最小验证项

建议任务：

- 确定页面 A 的手工验证步骤
- 确定批次 1 是否需要新增最小静态页面 smoke 或仅依赖人工验收
- 明确联调时至少要覆盖一条成功路径与一条失败路径

建议最小验证范围：

- 页面能打开
- 页面 A 能提交价格历史查询
- 页面 A 能展示成功结果
- 页面 A 能在非法输入或失败响应时展示最小错误提示
- 页面结构在空结果场景下保持稳定

当前不做：

- 复杂前端自动化测试体系
- 视觉回归体系
- 全页面 E2E 覆盖
