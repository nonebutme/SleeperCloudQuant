# 第一批候选文件映射清单

## 一、文档定位

- `已确认` 本文档是第一批候选文件映射的规划版，不是实际文件复制清单。
- `已确认` 本文档只定义第一阶段 4 个模块应从哪些来源仓库吸收哪类候选文件或候选目录。
- `已确认` 本文档不直接触发源码读取、文件复制、目录迁移或实现开发。

## 二、范围边界

### 2.1 纳入模块

- `data-platform`
- `backtest-kernel`
- `config-center`
- `reporting`

### 2.2 来源边界

- 主拼接来源：
  - `SleeperCloudQuant-old`
  - `TradingAgents-CN-main`
- 语义参考：
  - `rqalpha-master`
  - `vnpy-master`

### 2.3 当前不纳入

- `backtrader-master`
- `web-app`
- `ai`
- `factor-lab`
- 逐文件最终名单确认

## 三、使用规则

- 本文档中的“候选文件类别/候选目录类别”只用于规划来源范围。
- 本文档中的“目标落点目录”只用于指示未来归属方向，不代表立即创建或迁移。
- 若某项能力被标记为 `仅参考`，则不进入第一轮复制候选。

## 四、模块映射

### 4.1 `data-platform`

#### 来源仓库

- `SleeperCloudQuant-old`
- `TradingAgents-CN-main`

#### 候选文件类别或目录类别

来自 `SleeperCloudQuant-old`：

- 市场数据仓储抽象类
- 历史行情读取相关服务类
- 交易日历读取相关服务类
- 本地缓存相关目录
- 数据仓储适配相关目录

来自 `TradingAgents-CN-main`：

- provider 分层相关目录类别
- 外部来源隔离相关结构类别
- 配置驱动型数据接入相关结构类别

#### 目标落点目录

- `data_platform/repositories/`
- `data_platform/providers/`
- `data_platform/cache/`
- `data_platform/sync/`

#### 采纳方式

- 仓储抽象类：`直接采纳候选`
- 行情/交易日历读取服务类：`改造后采纳候选`
- 本地缓存目录：`直接采纳候选`
- provider 分层结构：`仅参考`

#### 不纳入原因

- 当前不纳入真实外部数据接入实现
- 当前不纳入复杂同步调度实现
- 当前不纳入财务数据、指数成分等扩展数据类别

#### 风险与待确认项

- 若仓储抽象与领域对象边界不一致，后续回测输入会返工
- provider 结构若直接照搬，可能引入不必要耦合

- 回测结果整理目录：`改造后采纳候选`

## 八、发布判断

### 已验证项

- 第一阶段 4 个模块已可以按“候选文件类别/候选目录类别”级别进入下一轮收敛
- 主拼接来源、语义参考来源和冻结参考来源已区分清楚

### 未验证项

- 具体哪些文件应进入首批候选名单
- 同一类别下是否存在多个互斥候选来源
- 各候选类别的授权边界是否完全明确

### 阻塞原因

- 当前仍未进入逐文件确认
- 来源仓库源码尚未按类别展开核对

### 潜在风险

- 若跳过类别级映射直接做逐文件确认，容易范围失控
- 若把结构参考误当成可直接复制来源，后续返工成本高

### 发布判断

- `已确认` 本文档可作为进入逐文件候选确认前的最后一层规划入口
- `待确认` 仍需你单独确认后，才建议进入下一阶段更细的文件级候选清单
