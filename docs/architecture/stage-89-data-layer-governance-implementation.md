# 阶段 89 数据分层治理实施基线

## 1. 范围与结论

- **已确认**：阶段 89.0—89.4 执行，89.5 暂不启动。
- **已确认**：运行数据采用“业务事实层 + 处理状态层”双轴治理，不通过移动表来伪造分层。
- **已确认**：`tmp/formal_http_demo.sqlite3` 已非破坏性提升为正式运行库
  `var/runtime/backtest_results.sqlite3`；源文件与迁移前备份继续保留。
- **边界**：本阶段不更换 SQLite、不拆微服务、不删除历史数据、不启动 89.5 的长期自动清理与存储重构。

## 2. 双轴数据分层

### 2.1 业务事实层

| 层级 | 定义 | 典型资产 |
| --- | --- | --- |
| F1 原始事实层 | 保留来源语义和来源标识的采集事实 | 行情、财务、分类、指数成分 |
| F2 标准事实层 | 完成代码、频率、复权和字段口径标准化 | 标准日线、证券主数据、交易日历 |
| F3 数据集层 | 面向研究与策略的可复现数据集合 | 策略数据集版本、股票池快照 |
| F4 因子层 | 因子定义、计算产物和值 | 因子目录、因子产物、因子值 |
| F5 策略层 | 策略输入、脚本和研究配置 | 策略工作区、研究配置 |
| F6 结果层 | 可审计的运行、回测及分析输出 | 回测运行、成交、持仓、账户、报告 |

### 2.2 处理状态层

| 层级 | 定义 | 使用原则 |
| --- | --- | --- |
| C1 控制与审计 | 同步任务、质量事件、纠错、版本和血缘 | 不替代业务事实，只描述其状态和证据 |
| X 兼容与缓存 | 可重建缓存、旧接口兼容表、临时投影 | 不得作为权威来源；必须声明来源和退出条件 |

一张表只能有一个主要业务层，但可同时具有控制属性。权威性由资产注册表声明，不能由数据库文件名、页面名称或表是否有数据来推断。

## 3. 权威来源与可用性

- `market.index_component_intervals` 是指数成分权威事实表；为空时，指数池能力必须返回 `empty/not_available`，不得退回演示数据。
- 因子产物只有存在 `ready` 产物时才允许策略消费；仅有目录定义时为 `connected`，不得展示为可执行。
- 旧因子重复表登记为 `deprecated_non_authoritative`，只用于迁移兼容。
- 纠错覆盖新增 `status` 与 `data_version_id`。新纠错默认 `pending_publish`；未绑定并发布到数据版本前，不能静默改变策略或回测输入。
- 资产、血缘和消费就绪度是运行时事实，由 API 暴露，不再仅存在于文档中。

## 5. 资产注册与血缘

资产注册表和血缘边位于市场权威库：

- `data_asset_registry`：数据库、表、业务层、权威状态、主键、时间字段、来源及保留类别。
- `data_lineage_edges`：来源资产、目标资产、转换类型、实现组件和说明。

当前机器可读目录登记 77 个表级资产、9 条关键血缘。它是治理最小闭环，不替代后续字段级血缘。

## 6. 性能与保留

阶段 89.4 为回测运行列表以及账户、持仓、成交、日志明细补充组合索引，并使用只读 `EXPLAIN QUERY PLAN` 验证命中。分析引擎内部需要完整序列时不允许静默截断；面向页面的列表仍必须使用显式分页参数。

保留策略由 `data_platform/retention_policy.py` 机器化表达，但本阶段不执行自动删除：

- F1—F6 权威事实和结果默认长期保留；
- 任务与质量审计在 365 天后仅成为归档候选；
- 可重建缓存在 30 天后仅成为清理候选；
- 兼容数据保留到消费者迁移验收；
- 阶段 89 迁移源与备份保留到正式验收之后，删除仍需单独批准。

## 7. 89.5 冻结项

以下内容均未启动：自动归档/删除任务、历史库冷热拆分、SQLite 替换、服务拆分、字段级全量血缘、旧兼容表物理移除。启动其中任一项前需重新确认范围、回滚方案和验收门槛。
