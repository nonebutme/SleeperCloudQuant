## 5. 主动质量发现闭环（2026-08-01 补充）

### 5.1 M2 与 M3 的职责边界

- M2“同步执行器”负责已知缺口的补齐、追更和同步任务执行，不负责证明已有记录正确。
- M3“质量检查与纠错”负责主动扫描未知问题、生成异常台账、受控修复和复查闭环。
- “M2 检查缺口没有缺失日期”只表示当前完整性规则未发现缺行，不等于 OHLCV、复权口径或其他质量规则通过。

### 5.2 主动发现流程

1. 用户在 M3 选择数据集、日期范围、股票范围、复权口径与质量规则。
2. 系统创建持久化质量检查任务，并在后台依次执行规则。
3. 页面展示任务状态、当前规则、规则进度、扫描记录数和问题数；离开页面后任务继续。
4. 每条发现写入统一 `data_quality_issues` 台账，携带证券、日期、规则、来源检查任务与结构化证据。
5. 用户可从检查历史直接“查看异常”，进入已经绑定该检查任务的筛选结果。
6. 修复后使用“复查”按原范围、原规则创建新任务；未再出现的父任务问题自动标记为已修正。

### 5.3 当前主动规则

- `missing_open_day`：交易日完整性，发现应有但缺失或不可用的交易日记录。
- `ohlcv_validity`：OHLCV 合法性，检查价格关系、负成交量/成交额及非数值记录。
- `adjustment_date_consistency`：复权口径日期一致性，检查 raw/qfq/hfq 在同一证券、同一交易日是否齐全。

### 5.4 任务状态与恢复

- `queued`：已创建，等待运行。
- `running`：正在检查；每完成一条规则更新一次进度。
- `passed`：所有规则执行完成，未发现问题。
- `issues_found`：所有规则执行完成，已生成问题台账。
- `failed`：检查失败，可在历史任务中重试。
- 服务重启时，未完成的 `running` 任务会转为 `failed` 并记录 `service_restarted_before_scan_completed`，避免永久假运行。
- 前端重试后会保底再次轮询，避免后台线程刚启动时首次读取旧状态而停止监控。

### 5.5 正式页面验证证据

- 检查任务：`quality-scan-20260801-1808fb8342`。
- 范围：A 股日线，2015-01-01 至 2026-07-30，全部当前股票，raw/qfq/hfq。
- 结果：3/3 规则完成，扫描 33,177,475 条规则记录，主动发现 14 条阻断异常。
- 构成：11 条复权口径日期不一致、3 条 OHLCV 非法；完整性规则未发现缺失交易日。
- 页面已验证：任务进度、终态、查看异常、组合筛选、问题详情、结构化证据和受控重拉入口均可见。

## 7. M3 异常处理交互闭环（2026-08-01）

### 7.1 选择与批量门禁

- 异常列表使用可访问复选框语义和 `☐/☑` 状态，不再使用含义模糊的“选择/取消”文字按钮。
- 选中后，原生源表与 VisActor VTable 同步使用主题主色浅背景高亮整行；表头支持全选当前列表。
- 批量操作默认禁用，只有“至少选择一条、全部属于同一数据集与同一规则、已填写统一判断依据”三个条件同时满足时才启用。
- 不满足条件时，页面就地说明是未选择、跨数据集/规则混选，还是缺少判断依据，不再只在点击后给出全局错误。

### 7.2 操作语义

- `确认可用并关闭提醒`：用于误报或已核实可用的观察；关闭当前提醒，不修改原始行情。
- `记录为不可用`：只记录该观察不可用；不删除、不屏蔽、不改写原始行情，通常还需生成修复任务。
- `暂缓处理（已隔离）`：证据不足时保留异常与证据，之后可继续判断或修复；不修改事实表。
- `人工修正`：在单条问题处理表单中写入修正覆盖层，保留原值、修正值、原因和操作人。
- `生成修复任务`：只创建 M2 待执行同步任务，不自动访问上游；用户须到 M2 审核并运行，完成后返回 M3 复查。

### 7.3 单条问题处理

- 每条异常提供“查看证据与处理”和“创建修复任务”入口。
- 详情区先展示问题性质判断说明，再展示规则、来源任务、结构化证据、历史治理结论与关联重拉任务。
- 创建修复任务成功后，页面明确返回可读任务 ID，并提示下一步前往 M2；避免用户误以为数据已自动修复。

- 已验证两条异常复选、整行选择状态、批量启用门禁、批量接受请求与清空选择、单条修复任务请求、详情历史、桌面与 741px 窄屏无页面级横向溢出，且无运行时异常。

### 8.3 真实异常处理与规则纠错

- 实测异常：`dqi-scan-116afc77f37bc0c54dc3f59d`，证券 `300333`，日期 `2026-07-29`，原判定为缺少 qfq。
- 页面创建修复任务 `a-share-sync-20260801-233131-6C9C27` 后返回“无需更新”；针对同一证券和日期重新检查仍复现异常，由此确认不是上游缺口，而是质量规则误报。

- 两条规则现已统一排除已登记非交易状态，并增加隔离数据库回归场景。
- 通过 M3 页面复查父任务 `quality-scan-20260801-233319-8493C3`，生成 `quality-scan-20260801-234439-4152C2`；3/3 规则通过、0 个问题，原异常自动转为“已修正”，审计记录为“复查未再次发现该问题，自动标记为已修正”。

## 10. M3 检查任务控制与异常处置防误操作（2026-08-02）

- 运行中的检查任务支持暂停、继续和停止。暂停/停止在当前规则完成后的安全边界生效，页面区分“等待暂停”“已暂停”“正在停止”“已停止”。
- 暂停不丢弃任务进度；继续从下一条待执行规则恢复。停止保留已完成规则结果和已登记异常，未执行规则不再运行。
- 每种异常结论在提交前展示“本次会做”“不会做什么”和“下一步”，并进行二次确认。
- “确认可用并关闭提醒”“记录为不可用”“暂缓处理”都不改写原始行情；“人工修正覆盖层”只写可审计覆盖层；“生成修复任务”只创建 M2 待执行任务。
- 标记为不可用后，通常流程为：生成修复任务 → 到 M2 审核并运行 → 回 M3 对来源检查任务执行复查；复查未再发现时，父异常自动进入已修正状态。
