### 3.1 频率与分片结论

- 已核实的上述 AKShare 文档没有声明统一的“每分钟调用次数”或服务可用性 SLA。
- 当前不能把“未声明限制”解释为“无限频率”。
- 下载器继续采用保守的全局限频、指数退避、断点续传、按标的/日期分片和失败隔离。
- 每个 provider 适配器必须支持独立配置频率；配置值是运行保护参数，不是供应商授权证明。

## 4. 目标数据分层

```text
外部 Provider
  -> 原始响应留痕/哈希
  -> 规范化事实表
  -> 数据质量报告
  -> 不可变数据版本清单
  -> published 版本
  -> 回测输入快照
  -> 结果与分析报告
```

### 4.1 规范事实层

仍以本地 SQLite 为主，不引入新数据库依赖。阶段 78.1 采用增量建表，不重写既有 `market_daily_prices`。

逻辑数据集：

1. `market_trade_calendar`
   - 主键：`market + trade_date`
   - 核心字段：`is_open`、`session_status`、`source`、`source_observed_at`、`source_payload_hash`
   - 约束：交易日历是独立事实，不能由“某只股票当天是否有行情”反推。

2. `security_lifecycle_events`
   - 主键：稳定 `event_id`
   - 核心字段：`symbol`、`event_type`、`effective_from`、`effective_to`、`announced_at`、`source`、`evidence`
   - 事件类型首期：上市、暂停上市、恢复上市、终止上市、重新上市、证券简称变更。
   - 约束：使用事件/区间模型，不在 `market_symbols` 上增加单一 `st_start/st_end`；同一证券可能发生多段状态。

3. `security_trading_status_daily`
   - 主键：`symbol + trade_date`
   - 核心字段：`status`、`is_tradable`、`suspension_reason`、`expected_resume_date`、`source`、`evidence`
   - 状态首期：`normal/suspended/resumed/unknown`。
   - 约束：`unknown` 必须保留，不能把行情缺失自动改写为 `suspended`。

4. `corporate_action_events`
   - 主键：稳定 `action_id`
   - 核心字段：`symbol`、`action_type`、`report_period`、`announcement_date`、`record_date`、`ex_date`、`pay_date`、`cash_ratio`、`bonus_ratio`、`transfer_ratio`、`status`、`source`、`source_payload_hash`
   - 约束：原始公司行动是不可变证据；方案更新通过新事件版本表达，不覆盖历史观察。

5. `price_adjustment_factors`
   - 主键：`symbol + trade_date + factor_method`
   - 核心字段：`factor`、`base_date`、`source`、`derived_from_action_version`、`quality_status`
   - 约束：复权因子与已复权 OHLC 分离；raw 永远保留，qfq/hfq 可以重建并追溯。

6. `market_index_daily_prices`
   - 主键：`index_symbol + trade_date`
   - 核心字段与 raw 日线一致，并记录指数发布方和来源。
   - 约束：正式基准与个股技术替代基准分开，报告必须披露基准身份。

### 4.2 版本与发布层

1. `data_versions`
   - `data_version_id`：不可变、全局唯一。
   - `status`：`draft/validating/published/rejected/superseded`。
   - `as_of_trade_date`、`created_at`、`published_at`、`quality_report_id`、`parent_version_id`。
   - 只有 `published` 可供新回测绑定。

2. `data_version_members`
   - 按数据集记录覆盖区间、标的数、行数、来源、同步 Run、内容摘要和质量状态。
   - 版本标识由规范化成员清单及其摘要确定，不用单个数据库文件修改时间生成。

3. `data_quality_reports`
   - 保存规则版本、检查输入、各规则结果、失败样本上限和最终结论。
   - 质量报告不可原地修改；修复后生成新报告并重新发布。

### 4.3 回测绑定契约

- 创建任务时解析一个明确的 `published data_version_id`。
- 同一任务及其全部 Run 默认使用同一版本；独立账户批量回测不得混合版本而不告警。
- `backtest_input_snapshots` 固化数据版本、数据集成员、复权口径、区间和资产键。
- 无可用发布版本时，正式回测应失败或进入明确的 `data_not_ready`，不能静默写入空版本。
- 历史 Run 不强制伪造版本；无法还原时保留 `not_bound/legacy_unverifiable`。

## 5. 质量门禁契约

### 5.1 发布级硬门禁

- 主键重复数为 0。
- 交易日历、证券生命周期与行情覆盖关系可解释。
- raw OHLC 满足 `high >= max(open, close, low)`、`low <= min(open, close, high)`，价格和成交量口径合法。
- 调整因子非空且大于 0；公司行动与因子变化能对账。
- 数据版本成员全部完成，不能引用仍在运行或失败的同步 Run。
- 正式指数基准覆盖回测期间，或报告明确降级为“无正式基准”。
- 每项失败都保留有限样本，禁止只给总数而没有证据。

### 5.2 不采用的错误规则

- 不要求“写入行数必须大于等于 API 返回行数”；增量去重后应使用输入、插入、更新、未变化、拒绝的数量守恒。
- 不要求复权因子单调；应验证正值、事件对账、连续性和计算口径。
- 不因少数复权价格异常而改写 raw 事实；异常进入隔离区并阻断对应版本发布。
- 不用当前分类、当前名称、当前 ST 状态回填历史时点。

## 6. 同步与自动调度决策

### 6.1 候选方案

| 方案 | 优点 | 边界 | 决策 |
|---|---|---|---|
| 应用内持久调度器 | 与本地 Web、同步状态和质量门禁一致，便于查看进度 | 应用关闭时不能执行 | 推荐为 78.2 首期 |
| Windows 任务计划程序 | 应用关闭也能拉起同步 | 修改操作系统状态，需要单独授权和安装/卸载说明 | 暂不实施，保留适配位 |
| 仅手动同步 | 风险最低 | 新鲜度依赖人工，无法满足稳定盘后更新 | 仅作为回退方式 |

### 6.2 推荐运行契约

- 交易日 18:15 后检查上游是否已完成收盘数据更新。
- 先同步交易日历和目录，再同步 raw 行情与指数，再同步上下文事实，最后生成质量报告和发布版本。
- 若 18:15 数据未就绪，采用有上限的指数退避，不持续高频轮询。
- 应用启动时执行“错过任务补偿”，但同一交易日只允许一个有效调度 Run。
- qfq/hfq 在 raw 与公司行动证据通过后生成或校验，不能先于 raw 发布。
- 单个标的失败不破坏旧的 `published` 版本；新版本保持 `draft/rejected`。
- 手动同步、自动同步、补偿同步统一进入同一状态机和审计表。

## 7. 迁移与回退方案

### 7.1 迁移原则

- 阶段 78.1 只做加法：创建新表、新索引、新适配器和读写接口。
- 首轮不删除、不重命名、不改变 `market_daily_prices` 的主键和既有读取语义。
- 先 dry-run 和小样本，再影子写入，再双读核对，最后切换新回测默认绑定。
- 每个迁移单元有独立 schema 版本、前置检查、后置检查和执行记录。
- 迁移前生成 SQLite 一致性检查结果和可恢复备份；WAL 必须正确 checkpoint。

### 7.2 最小迁移单元

1. 版本/质量元数据表。
2. 交易日历与指数日线。
3. 证券生命周期与日交易状态。
4. 公司行动与复权因子。
5. 回测版本解析和强绑定。
6. 调度状态机。

每个单元验证通过后才能进入下一个单元。

### 7.3 回退

- 保留旧读路径的功能开关；新路径失败时回到旧数据读取，但必须显示“未绑定正式版本”。
- 新表失败时停止写入并恢复到迁移前备份，不删除旧表。
- 已发布版本不可篡改；错误版本标记为 `superseded/rejected`，由新版本替代。
- 调度器可停用并回到手动命令，不清理历史同步 Run 和质量报告。
