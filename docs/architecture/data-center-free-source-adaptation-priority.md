# 数据中心免费数据源适配评估与优先级

## 1. 结论

- 评估日期：2026-07-30。
- 使用边界：仅用于本地、非商用量化研究；“可免费访问”不等于获得商用授权，也不构成可用性 SLA。
- 受控目录现已包含 9 项：AKShare、BaoStock、mootdx、腾讯财经、i问财、东方财富研报、AKShare 同花顺、巨潮资讯、a-stock-data。
- 仅 AKShare 为 `verified + enabled`；其余 8 项均为 `candidate + disabled`，不能进入同步路由。
- 本轮未安装依赖、未调用候选上游、未新增正式路由，也未改写行情事实。

## 2. 判定口径

按以下维度评估：免费可访问性、官方/项目文档完整度、与现有 AKShare/SQLite 架构的复用程度、接口与授权边界确定性、对现有数据集缺口的价值。任何候选源只有同时通过契约测试、字段映射、限频、质量对账、授权边界记录后，才可从 `candidate` 晋升为 `verified`。

## 3. 适配优先级

| 优先级 | 数据源 | 定位 | 免费与实现判断 | 主要价值 | 当前阻塞 |
| --- | --- | --- | --- | --- | --- |
| P0 | AKShare | 当前主源 | 已安装、已有正式适配器和受控路由 | 继续承担行情、目录、日历、板块、资金流、事件 | 免费上游无 SLA，端点仍需持续健康检查 |
| P1 | AKShare 同花顺 | 同依赖增量适配 | 无需新增包，官方 AKShare 数据字典已列出同花顺行业/概念接口 | 补强行业板块、概念板块，降低东财单源依赖 | 需做返回字段、反爬行为、频率和历史覆盖验证 |
| P1 | 巨潮资讯（优先经 AKShare 封装） | 公告与公司事实 | 巨潮公开披露页面已确认；优先复用 AKShare 已文档化的巨潮能力 | 公告、行业归属变更、股本变动等权威披露事实 | 未确认巨潮直接自动化 API 合约；先禁用直连 |
| P2 | BaoStock | 第二独立日线源 | 官方站点称无需注册，适合作为免费候选；需新增包和适配器 | 日线、证券目录、交易日历、财务字段交叉校验 | 新依赖需人工批准；需核对更新时效和字段口径 |
| P2 | mootdx | 行情/本地文件备源 | MIT 项目，但仓库明确限定学习交流，符合本项目当前非商用边界 | 在线 K 线、指数及本地通达信文件读取；可做行情备源 | 需新增依赖；节点稳定性、复权正确性和市场扩展接口有风险 |
| P3 | 东方财富 reportapi | 研报目录候选 | 官方研报网页存在，但未找到官方开放 API 合约 | 填补 `research_reports` 数据集 | 数据来源含 Choice；接口、版权、PDF 下载与限频边界不明确 |
| P3 | 腾讯财经 | 行情补充候选 | AKShare 文档存在腾讯历史行情能力，但腾讯直连接口没有确认的官方开放合约 | 快照估值/市值或历史行情交叉校验 | 直连协议未公开，字段易变；应先走 AKShare 受控封装 |
| P4 | i问财 | 交互查询候选 | 自然语言网页服务可用不代表免费开放 API | 选股/概念研究的探索性补充 | 会话鉴权、反自动化、结果复现和授权边界均不清晰 |
| 参考轨 | a-stock-data | 第三方实现参考，不是数据源 | Apache-2.0 代码仓库可研究，但其内部仍连接 15 个上游并安装多项依赖 | 借鉴端点清单、降级设计、字段处理与失败经验 | 不能整体作为可信上游；需逐端点考古、许可和契约验证 |

## 4. 推荐实施顺序

1. P1-A：在现有 AKShare 依赖内，为同花顺行业/概念接口建立只读契约探测；输出字段样本、空值率、日期覆盖和与东财数据的差异报告。
2. P1-B：通过 AKShare 已文档化的巨潮接口补公告与公司事实；只保存索引和必要结构化事实，原文链接保留来源，不批量搬运受版权保护内容。
3. P2-A：单独申请新增 BaoStock 依赖；先做交易日历与少量日线影子对账，不替换 AKShare 主路由。
4. P2-B：单独申请 mootdx 依赖；先做本地文件读取和指数/日线影子源，复权未通过对账前禁止发布。
5. P3：东方财富 reportapi、腾讯财经只做隔离探测；找不到官方接口合约时不得晋升正式源。
6. P4：i问财不进入自动同步主链；a-stock-data 仅作为代码考古材料，逐项提取可验证思想，不整体集成。

## 5. 晋升门槛

每个候选适配必须同时满足：

- 明确来源页面、项目许可或使用条款，并记录非商用适用边界；
- 固定 endpoint、允许主机、超时、限频、重试和熔断策略；
- 通过字段 schema、代码映射、时区/交易日、复权口径测试；
- 与本地已发布版本进行小样本及多交易日对账，差异可解释；
- 探测只读，失败不写正式事实，写入先进入未发布观察/隔离层；
- 经人工确认后才允许从 `candidate` 改为 `verified`，再单独批准正式路由。

## 7. 当前发布判断

候选目录补齐可以作为阶段 86 数据中心候选基线的一部分继续使用。它只提升“可见性与治理完整性”，不代表新增八个接口已经适配完成；下一步最合理的是 P1 的 AKShare 同花顺和巨潮封装契约验证。P2 涉及新增依赖，仍需人工批准。
## 8. P1 契约验证更新（2026-07-30）

P1 只读验证后已继续完成同花顺优化：概念映射缓存、15秒请求上限、跨源代码解析和统一 `on_failure` 路由均已落地，20板块×3日复验通过，AKShare 同花顺已晋升为已验证回退源。巨潮仍因公告非 JSON 与行业变更 SSL EOF 保持停用候选。详细证据见 `docs/verification/data-center-p1-source-contract-validation.md`。


## 9. P1-B 巨潮适配更新（2026-07-31）

巨潮已从“未实现直连候选”升级为“受控 HTTP 候选”：公告、行业目录、行业变更、股本变更共用限时、有限重试、TLS 强校验和错误分类客户端。公告、行业目录、股本变更通过单样本契约；行业变更仍受 TLS EOF 阻塞。

因此优先级不变：巨潮继续位于 P1，但整体保持 `candidate + disabled`。已通过的三个能力也保持停用，仅作为后续人工晋升的端点级证据；行业变更稳定性和多证券对账完成前，不增加正式路由。

## 10. P1-B 行业变更门禁更新（2026-07-31）

系统 curl TLS 回退解决了 Python OpenSSL 与 `p_stock2110` 的兼容问题，同时修正了“多行业标准错误串联”为单一时间线的语义缺陷。10 只代表证券、107 条全历史行业记录通过标准内区间契约。

巨潮四项能力均已达到 `verified + disabled`，但数据源整体仍保持 `candidate + disabled`。下一步不是自动启用，而是人工决定是否将巨潮晋升为受控正式源，以及公告、行业分类/变更、股本变更分别采用何种正式路由策略。

## 11. 巨潮安全晋升结果（2026-07-31）

人工批准后，巨潮已晋升为 `verified + disabled`，四条正式路由以停用状态登记。10 证券只读影子同步返回行业 107 条、股本变更 442 条、公告 74 条，行业分类与本地基座 10/10 一致；全程写入 0、未发布。

行业目录首轮 403 在完整限频周期后单次重试恢复，表明适配契约成立但免费上游仍可能短时拒绝。下一步应按风险从低到高分别批准路由：优先行业分类/变更的 `fill_missing`，再评估股本变更与公告；不建议一次性启用四条。
## 12. 巨潮行业路由启用结果（2026-07-31）

人工批准后，巨潮数据源及行业目录、行业变更两条 `fill_missing` 路由已启用；公告与股本路由继续停用。正式 `.venv` 通过 Windows CNG 生成与 PyCryptodome 完全一致的 AES 请求头，无需新增依赖。

- 当前优先级：巨潮行业分类由“验证候选”进入 P1 受控补缺运行。
- 路由边界：只填补缺失分类，不替换既有发布事实，不自动触发全市场同步。
- 下一门禁：观察实际任务成功率、403/TLS 失败率和分类冲突率后，再决定是否批准公告或股本路由。

## 13. 巨潮行业补缺正式任务结果（2026-07-31）

单证券正式受控任务已验证“已有覆盖不重复写入”：`000001` 本地与巨潮当前分类一致，任务冻结两条行业路由快照后以 `completed_noop` 完成，写入 0、未发布。下一优先门禁是选择一个本地确实缺少行业分类的证券验证写入分支；不得为了制造样本删除既有事实。
