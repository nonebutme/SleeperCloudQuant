# 阶段 91.0—91.3：数据源有效性与质量修复闭环

## 已确认范围

- 91.0：冻结数据源、能力、探测、任务配置、质量问题、修复工单、版本发布与复检的契约。
- 91.1：数据源配置进入任务快照并由执行器实际消费；数据源测试按能力执行只读探测，记录结构化错误与零业务写入证据。
- 91.2：统一重拉、历史补齐和人工纠错覆盖的修复工单；只有生成有效数据版本并通过定向复检后，问题才能进入 `corrected`。
- 91.3：数据源能力与凭据状态、探测历史、任务冻结/实际配置、问题时间线和发布就绪度进入数据中心工作台。
- 91.4：未启动；持续健康度、趋势、自动回退、分页与导出规则仍不在本阶段范围。

## 核心实现

1. `data_source_probes` 保存能力级探测结果、延迟、样本量、错误码、错误类别和可重试性。连接测试不启用数据源、不写业务事实。
2. `data_route_snapshots.snapshot_json.effective_config` 与 `market_incremental_sync_jobs.effective_config_json` 共同冻结创建时配置；执行前应用并写入 `actual_config_json`，用于证明配置真实生效。
3. `allowed_hosts` 在真实探测前校验；密钥只读取环境变量是否存在，API 和数据库不保存或返回值。
4. `data_quality_remediations` 统一承载 `refetch`、`historical_backfill` 和 `correction_overlay`。状态按 `remediating → awaiting_publish/awaiting_recheck → corrected|failed` 演进。
5. 人工纠错只生成覆盖层，不修改原始行情。发布覆盖层生成不可变新版本，定向复检读取该覆盖；复检不再发现同一问题后才关闭工单。标准行情读取只合并全局默认版本所属覆盖，不因新版本发布而提前改变默认口径。
6. 发布就绪度统一检查阻断型质量问题、待发布覆盖和待完成修复工单。执行器自动发布和数据中心人工发布均接入门禁；当前任务或当前纠错工单只允许窄范围自豁免。

## 安全与边界

- 不自动启用或切换数据源，不新增适配器，不改变付费/授权边界。
- 不自动切换全局默认数据版本；历史 Run 仍绑定原版本。
- 不物理重写历史事实，不倒推指数快照以前的事实。
- 正式指数点时事实导入、阶段 91.4、新依赖和结构性改动仍需单独确认。
