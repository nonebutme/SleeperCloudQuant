# 阶段 65｜直接 CNInfo 并发与全市场自动恢复

## 目标

移除 AKShare py_mini_racer 在逐标的行业同步中的性能和稳定性瓶颈，让全市场历史行业任务自动连续运行，同时保留阶段64的断点恢复与审计状态。

## 实现

- 使用 pycryptodome 按 CNInfo 官方前端逻辑生成 Accept-Enckey AES-CBC/PKCS7 时间戳签名。
- 直接调用 p_stock2110 HTTP 接口，不再为每个标的启动 JavaScript 引擎。
- 默认 2 个工作线程，支持 --request-interval 全局请求间隔。
- 重试采用 5/10/20 秒指数退避并附加随机抖动。
- 保留 pending、failed 状态筛选，可先完成未尝试队列，再单独回收失败队列。
- 全量任务不再限制每批100个，可一次启动后持续处理全部剩余队列。

## 真实验证

- 单标的验证：1/1 成功，写入10个历史行业区间。
- 4标的、2并发验证：4/4 成功，写入54个区间。
- 20标的突发压测：8/20 成功，证明 CNInfo 存在明显 TLS/限流边界。
- 10标的、2秒全局间隔验证：8/10 成功，写入115个区间，无运行时崩溃。
- 完整 scripts/run_formal_verifications.py：全部通过。
- 生产恢复任务使用2并发、2秒间隔、3次重试，任务状态持续写入 classification_sync_state。

## 边界

CNInfo 的 p_stock2110 是单证券代码查询接口，无法确认支持多代码批量请求。加速目标因此是移除 JavaScript 开销、自动连续运行和稳定有限并发，而不是无限提高并发。
