# 阶段 86：免费数据源候选评估

时间：`2026-07-28`

## 1. 已确认边界

- 项目不作商用，仅用于本地量化研究。
- 优先选择免费、无需购买账号套餐、可由当前 Python/AKShare 技术栈实现适配的接口。
- 免费可访问不等于获得上游数据再分发权、稳定性承诺或服务 SLA。
- 阶段 86.0 只做来源评估，不执行同步、不修改依赖或 Provider 配置。

## 2. 首选技术路线

继续使用现有 AKShare 依赖作为首期聚合适配层，原因：

1. 项目已存在 AKShare Provider、限频、重试、隔离和来源审计实现。
2. 不需要引入新依赖或密钥。
3. 可覆盖当前 A 股研究所需的行情、指数、日历、目录、公司行动、行业和财务候选接口。
4. Provider 层可隔离上游字段变化，不把 AKShare DataFrame 直接暴露为项目公共契约。

AKShare 官方说明其接口采集公开数据，主要用于学术研究，并明确提醒商业风险。当前非商用定位与其公开说明基本一致，但项目仍保留来源审计和停用能力。

## 4. 不作为首选的方案

- 需要购买积分、套餐或商业账号才能稳定覆盖核心范围的数据服务。
- 需要在代码、文档或数据库中保存明文密钥的接口。
- 不能说明来源、抓取时间或字段含义的聚合接口。
- 只能提供当前截面、却被要求回填历史行业、历史成分或历史财务可得时间的接口。
- 依赖未审计网页结构且无失败隔离的直接抓取代码。

## 5. 接入门禁

每个候选接口进入正式同步前必须完成：

1. 单请求字段与类型探测，不写主库。
2. 小样本日期、资产、空值、重复和单位校验。
3. 来源网站、接口名、适配器版本和抓取时间留痕。
4. 明确限频、超时、重试和隔离策略。
5. 与现有正式版本双读或影子写比对。
6. 质量失败时保留旧 `published` 版本。
7. 统一正式验证和人工数据边界审批。

## 6. 财务数据特别边界

- 报告期不是可用时间；必须保存公告日或首次观察时间。
- 财务更正、快报与正式报告不得无审计覆盖。
- 同比、环比和 TTM 指标只能基于明确可得的历史事实计算。
- 在点时模型完成前，财务因子不得进入正式因子研究报告。

- `推荐`：阶段 86.1 继续复用 AKShare，按数据集建立显式 Provider 路由和失败隔离。
- `不推荐`：为了接口数量同时引入多个免费库；这会扩大字段冲突、维护和来源审计成本。
