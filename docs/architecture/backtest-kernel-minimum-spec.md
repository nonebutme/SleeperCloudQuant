# 回测内核最小规格规划

## 一、文档定位

- `已确认` 本文档是回测内核的最小规格规划版，不是实现文档。
- `已确认` 本文档只定义第一阶段最小回测闭环的能力边界、输入输出与阶段划分。
- `已确认` 本文档不直接触发回测执行代码编写、运行时接入或数据库落地。

## 二、输入来源

- `docs/architecture/phase-1-stitching-plan.md`
- `docs/architecture/domain-boundary-spec.md`
- `docs/architecture/quant-platform-recomposition-plan.md`
- `docs/code-archaeology/candidate-capability-routing.md`

## 三、范围边界

### 3.1 纳入范围

- `BacktestGateway`
- `BacktestRequest`
- `BacktestResult`
- 回测运行入口
- 适配层边界
- 结果存储边界
- 指标提取边界
- 日志与状态边界
- 报告衔接边界

### 3.2 当前不纳入

- `rqalpha` 实际运行时接入
- 具体策略代码加载实现
- 数据库表设计
- API 接口设计
- Web 任务调度与页面状态联动

## 四、模块目标

第一阶段回测内核只服务于以下目标：

1. 接收一个标准化 `BacktestRequest`
2. 通过统一回测入口启动执行
3. 通过适配层对接首个运行目标
4. 产出标准化 `BacktestResult`
5. 保留最小运行日志、状态与指标摘要
6. 为 `reporting` 提供稳定结果输入

## 五、总体设计原则

### 5.1 已确认

- 回测内核优先形成“请求 -> 执行 -> 结果”三段式最小闭环。
- 主抽象优先承接 `SleeperCloudQuant-old` 的回测服务思路。
- 运行语义优先对齐 `rqalpha-master`，但当前不整合其源码。
- 核心对象必须与 `domain-boundary-spec.md` 保持一致。

### 5.2 基于当前上下文推断

- 回测内核当前最重要的是统一边界，而不是追求多运行时兼容。
- 第一阶段应默认单回测任务、单账户、单运行目标优先。

## 六、最小闭环流程

### 6.1 请求阶段

- 接收一个 `BacktestRequest`
- 校验最小必要参数
- 生成回测任务上下文
- 准备执行所需数据范围与策略引用信息

### 6.2 执行阶段

- 通过统一 `BacktestGateway` 发起回测
- 将标准化请求转换为运行时可理解的配置
- 记录关键运行状态
- 接收回测执行输出

### 6.3 结果阶段

- 将执行输出标准化为 `BacktestResult`
- 抽取最小指标摘要
- 记录最小日志摘要
- 提供结果存储入口
- 提供给 `reporting` 的读取边界

## 七、核心能力规格

### 7.1 `BacktestGateway`

#### 职责

- 作为统一回测入口抽象
- 隔离外部运行时差异
- 承担请求转换、执行调用和结果回收的总边界

#### 最小输入

- `BacktestRequest`
- 策略入口引用
- 数据范围上下文
- 运行参数

#### 最小输出

- 标准化执行结果原始包
- 运行状态摘要
- 原始日志或事件摘要

#### 语义来源

- `主参考` `SleeperCloudQuant-old`
- `补充参考` `rqalpha-master`

#### 待确认

- `BacktestGateway` 是接口式抽象还是服务式抽象
- 是否需要显式区分同步执行与异步执行语义

### 7.2 回测运行入口

#### 职责

- 作为应用层触发回测的统一入口
- 协调请求校验、执行调用、结果标准化和落盘

#### 最小输入

- `BacktestRequest`

#### 最小输出

- `BacktestResult`

#### 边界要求

- 不直接持有运行时细节
- 不直接耦合报告生成逻辑
- 不直接承担数据库结构定义责任

#### 待确认

- 入口是单一服务还是任务型服务
- 首阶段是否需要回测任务编号与追踪上下文分离

### 7.3 适配层边界

#### 职责

- 把统一请求对象转换为首个回测目标运行时的输入
- 把运行输出转换为统一结果语义

#### 当前首个目标

- `rqalpha-master`

#### 最小转换内容

- 账户初始参数
- 回测区间
- 标的范围
- 策略参数
- 执行频率

#### 当前不做

- 多运行时适配并存
- 多市场统一适配
- 直接复用外部运行时工程结构

#### 待确认

- 转换层是否需要拆成 `request-adapter` 与 `result-adapter`
- 数据准备逻辑位于适配层还是位于执行前服务层

### 7.4 结果存储边界

#### 职责

- 为标准化 `BacktestResult` 提供统一存储入口
- 保证历史结果可查询、可复用、可报告引用

#### 最小存储范围

- `request_id`
- `result_id`
- 运行状态
- 开始/结束时间
- 指标摘要
- 账户快照摘要
- 订单/成交摘要
- 日志摘要引用

#### 边界要求

- 存储层只处理标准化结果，不处理运行时原始结构
- 不在当前阶段绑定具体数据库实现细节

#### 待确认

- 日志摘要是直接存结果还是单独引用
- 订单与成交是否首阶段只存摘要不存明细

### 7.5 指标提取边界

#### 职责

- 从回测输出中抽取最小可读指标集
- 为结果查询和报告层提供稳定指标摘要

#### 最小指标范围

- 收益率
- 年化收益率
- 最大回撤
- 夏普比率
- 胜率
- 交易次数

#### 边界要求

- 当前阶段优先保留摘要指标
- 不在本阶段扩展为完整因子评估或全量绩效分析框架

#### 待确认

- 指标定义是否完全跟随首个运行目标
- 指标计算结果是统一重新计算还是尽量承接运行时输出

### 7.6 日志与状态边界

#### 职责

- 表达一次回测的最小过程可观测性
- 支撑失败诊断、状态查询和结果回放入口

#### 最小状态范围

- `pending`
- `running`
- `succeeded`
- `failed`

#### 最小日志范围

- 请求接收时间
- 执行开始时间
- 执行结束时间
- 失败原因摘要
- 关键阶段事件摘要

#### 边界要求

- 状态对象与结果对象保持可关联但不完全耦合
- 当前阶段不引入复杂事件总线或实时日志流

#### 待确认

- 是否需要单独的运行记录对象
- 失败诊断信息是否保留错误码语义

### 7.7 报告衔接边界

#### 职责

- 为 `reporting` 层提供稳定输入
- 明确回测结果与回测报告之间的依赖边界

#### 最小输出给 `reporting`

- 回测摘要
- 指标摘要
- 风险摘要
- 订单/成交摘要
- 观察性日志摘要

#### 边界要求

- `backtest-kernel` 只输出标准化结果，不负责生成最终报告文本
- 报告层不得反向要求回测层暴露运行时内部实现细节

#### 待确认

- 风险摘要是在回测层输出还是由报告层二次加工
- 图表数据是否首阶段需要从回测层预留引用能力

## 八、运行阶段划分

### 8.1 `prepare`

- 请求合法性校验
- 参数规范化
- 策略与数据上下文准备

### 8.2 `dispatch`

- 把请求送入统一网关
- 绑定首个运行目标适配层

### 8.3 `execute`

- 调用首个运行目标执行
- 跟踪最小运行状态

### 8.4 `normalize`

- 把运行输出转换为标准化结果
- 抽取指标与摘要

### 8.5 `persist`

- 写入结果存储入口
- 为报告与历史查询保留引用

## 九、与来源项目的承接关系

### 9.1 承接 `SleeperCloudQuant-old`

- `BacktestGateway` 主抽象
- `BacktestRequest / BacktestResult` 主对象边界
- 回测服务层组织思路
- 结果落盘与回测报告衔接思路

### 9.2 对齐 `rqalpha-master`

- 账户语义
- 订单语义
- 持仓语义
- 回测配置组织语义
- 执行生命周期语义

### 9.3 补充 `vnpy-master`

- 交易对象统一语义
- `Order / Trade / Position / Account` 的通用对象表达

## 十、前置依赖

- 第一阶段来源范围已经锁定为 `SleeperCloudQuant-old` 主承接 + `rqalpha-master` 语义对齐

- 不定义全量报告模板生成

## 十三、发布判断

### 已验证项

- 回测内核第一阶段的最小闭环边界已经从请求、执行、结果、日志、指标、落盘、报告衔接七个方面收敛
- 主承接来源、语义对齐来源和补充语义来源已区分清楚

### 未验证项

- 首个运行目标的具体适配复杂度
- 指标摘要是否完全承接运行时输出
- 日志摘要与结果对象的最终耦合方式

### 阻塞原因

- 当前仍未进入字段级实现确认
- 数据平台输入边界与结果存储边界还需后续最小规格文档配合

### 潜在风险

- 若跳过统一网关抽象直接接入运行时，后续替换成本会很高
- 若回测结果与日志边界不清，报告层会反向侵入执行层

### 发布判断

- `已确认` 本文档可作为进入回测相关实现前的最小规格基础
- `待确认` 仍不应把本文件直接视为最终实现契约
