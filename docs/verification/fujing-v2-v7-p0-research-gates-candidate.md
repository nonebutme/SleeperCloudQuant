# 拂经 v2 V7 P0 研究门禁候选验收

## 一、结论

- 状态：`机制可交付，业务数据仍受门禁阻塞`
- 本轮形成了三个可执行、无业务数据写入的候选门禁：字段级数据契约、预热/评估分离与共同覆盖、样本前缀稳定性因果负向门禁。
- 字段契约、预热/评价分离、共同覆盖和因果负向门禁已接入策略保存、resolver 及三类正式回测路径。
- `scripts/fujing_v2_strategy.py` 第 6 版未修改；本轮也未创建第 7 版策略。

## 二、已确认语义对应

1. WINNER 保留日频代理，正式名称必须包含 `proxy`，不得表述为原生筹码分布。
2. 低点采用仅依赖当前及过去数据的 16 日因果低点。
3. 固定 0.04 元振幅改为相对昨收比例；阈值尚待开发样本研究和冻结。
4. 正式研究股票池采用点时全 A 股；固定样本仅用于冒烟。
5. 样本外窗口在查看前封存；查看后如改动任何策略、参数、数据或因子，原窗口降级为开发证据。

## 三、已验证项

- `strategy_research_preflight.py` 可从策略源码的字面量 `DATASET_CONTRACTS` 解析字段、最小历史、复权、点时、缺失、版本和覆盖模式。
- 字段不存在、复权不支持、声明与契约集合不一致时返回明确失败项。
- `validate_prepared_research_window` 将评估起点之前的数据只计入 warm-up，并检查 warm-up 行数。
- 对 `same_trade_date` 数据集执行共同覆盖检查；缺失且策略为 `unavailable/fail` 时拒绝。
- `strategy_causality_gate.py` 通过多处截断输入，验证历史权重和分数是否随未来数据出现而变化。
- 新增烟雾测试通过：`python scripts/smoke_test_fujing_v7_research_gates.py`。
- 新文件通过 `python -m py_compile`。
- 旧解析器烟雾：`smoke_test_strategy_dataset_resolver.py` 通过。
- 严格策略会自动向评价期之前扩展保守取数窗口，warm-up 参与信号计算但不计入收益、交易与评价 bars。
- 点时证券目录要求 `fetch_symbol_history` 区间事实；当前名称复制到历史 bars 的方式不再被严格策略接受。
- OOS 冻结清单及首次查看记录已使用追加式 SQLite 服务持久化并验证不可变性。
- `python scripts/run_formal_verifications.py` 完整通过，最终输出 `[formal] all verifications passed`。

## 四、未验证项

- 尚未补齐历史 ST/风险警示、名称与上市/退市区间事实，点时全 A 股仍不具备正式数据条件。
- 尚未冻结振幅比例阈值、开发窗口、封存样本外窗口及主次评价指标。
- 因果门禁是给定样本上的负向测试，不是对任意输入的形式化证明。

## 五、阻塞原因

- Windows sandbox 与 `apply_patch` 已恢复；既有服务和统一 runner 已完成接线。
- 当前实际阻塞转为业务数据：缺少获授权的历史风险警示、名称、上市/退市区间事实及其质量证据。
- 样本外数值阈值仍需用户在开发样本研究后、首次查看 OOS 前确认。

## 六、潜在风险

- 若绕过正式接线直接宣称门禁生效，会产生错误安全感。
- `a_share_catalog` 当前不是历史区间事实；即使字段契约通过，也不能证明历史 ST 过滤正确。
- 共同覆盖必须同时覆盖 warm-up 和 evaluation，不能只检查用户输入的评估日期。
- OOS 封存已经具备不可变存储，但尚未接入 Web 操作入口和用户身份审计。

3. 待数据和研究门禁满足后，创建 V7 候选并完成 V6/V7 逐日信号对拍。

5. 生成正式 OOS 封存清单后才允许执行和查看样本外结果。
