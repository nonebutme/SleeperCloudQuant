# 拂经 v2 V7 证券主数据版本绑定验收

## 已验证项

- `security_master_intervals` 的区间身份包含 `evidence.job_id`：同一快照重复写入保持幂等，不同快照不会覆盖旧版本区间。
- 数据版本成员以 `details.snapshot_refs` 冻结证券主数据快照，并兼容单一 `sync_run_ref`。
- 显式读取只接受 `published/superseded` 版本、`passed` 成员及非空快照引用；缺版本、缺成员、损坏详情或空引用均失败关闭。
- 黄金测试先发布含 ST 切换的 V1，再发布全非 ST 的 V2；活动读取命中 V2，显式 V1 仍准确回放三段旧区间。
- 严格 `as_of_trade_date` 目录契约缺少 `data_version_id` 时拒绝运行；单标的、独立账户批量与共享组合回测均透传冻结版本。
- 真实库审计：6,443 个活动候选区间、5,227 只证券；默认正式版本未包含证券主数据成员，因此状态为 `candidate_only`、消费者访问为 `not_available`。
- `python -B scripts/run_formal_verifications.py` 退出码 0，输出 `all verifications passed`。

## 潜在风险

- 版本机制只保证“按冻结快照重放”，不证明候选事实本身完整、授权充分或时间语义足够精细。
- 若未来发布成员遗漏任一组成快照引用，显式版本读取会出现覆盖缺口并由 resolver 失败关闭。
