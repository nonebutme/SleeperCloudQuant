# 数据版本成员一致性门禁验收

验收日期：2026-08-19

## 已验证项

- 已确认增量发布器此前仅重算行情、交易日历和沪深 300 成员，
  `security_trading_status_daily` 会从上一发布版本原样继承；正式物理表已更新时，这会造成
  版本成员的行数和日期边界滞后。
- 发布器现将 `security_trading_status_daily` 排除出继承集合，并在每次发布时从规范物理表
  重新生成行数、证券数、最早/最晚日期、内容摘要、来源和本次任务引用。
- 发布前新增可变成员一致性门禁，逐项比较以下成员与规范物理表的 `row_count`、
  `symbol_count`、`min_date`、`max_date`：
  - `market_daily_prices`（按复权口径）；
  - `market_trade_calendar`（CN）；
  - `market_index_daily_prices`（000300）；
  - `security_trading_status_daily`。
- 成员重复、缺失或任一摘要不一致时，发布器抛出
  `release member consistency blocked` 并拒绝创建发布版本。
- 既有已发布版本保持不可变；修复只影响服务重启后创建的新版本。
- `scripts/smoke_test_stage78_2_incremental_scheduler.py` 已增加正向成员核对和篡改摘要的
  反向阻断用例，专项回归通过。
- 对正式规范库完成零写入预检：新成员生成与物理摘要复核通过，交易状态为
  11,345,287 行、5,642 个证券，日期范围 2014-10-28 至 2026-08-17。

## 未验证项

- 尚未在正式 18GB 规范库上创建修复后的新 `qfq`/`hfq` 发布版本。
- 尚未通过 M5 页面人工核对新版本的交易状态成员展示。
- 门禁当前核对可变成员的汇总身份，不逐行重算 1100 万级交易状态内容哈希。

## 阻塞原因

- 当前 8010 服务进程是在代码修复前启动的，必须由操作者重启后，新任务才会加载本门禁。
- 正式版本发布属于有状态业务操作，应继续由用户按人工操作指南串行执行。

## 潜在风险

- 汇总一致不能替代字段级、逐行内容审计；现有质量规则和唯一键约束仍须共同生效。
- 如果物理表在成员生成与门禁复核之间被另一个写任务并发修改，门禁会拒绝发布；这是
  预期的保守行为，应停止并排查并发写入，而不是绕过门禁。
- 旧版本保留旧成员事实，不应因当前物理表已前进而回写历史版本。

## 发布判断

- 版本成员一致性代码门禁：`专项自动化通过`。
- 正式新版本成员：`待服务重启并完成下一次 qfq 发布后人工确认`。
- 产品、策略有效性及实盘可用性：`不能据此发布`。
