# 数据中心参考数据受控刷新验收

验收日期：2026-08-18

## 已验证项

- 数据中心服务新增参考数据零写入预览：返回当前证券目录、交易日历、目标日前最近开市日、
  沪深 300 日线基准和交易状态观察日期。
- 预览不调用上游、不修改规范库，并签发 15 分钟有效的一次性令牌。
- 写入刷新必须持有与目标日期一致的有效预览令牌；令牌在校验时消费，不可复用。
- 刷新只调用既有受治理调度器，写入证券目录、交易日历和沪深 300 日线；完成后重新读取
  覆盖，并要求交易日历与基准共同满足发布门禁。
- 增量价格任务在工作项完成后，会把成功取得规范行情的证券日物化为正常可交易状态；
  已有停牌事实优先且不会被覆盖，从而补齐 V7 严格逐 bar 交易状态绑定。
- 增量发布不再继承旧的交易状态版本成员；每次发布都会从规范物理表重算成员，并在
  落版前核对可变成员的行数、证券数和日期边界，不一致即拒绝发布。
- 目标日前最近开市日按 `trade_date <= target_date` 计算，历史目标不会被数据库内更晚日历
  误判。
- 新增 API：
  - `POST /api/data-center/sync/reference-data/preview`
  - `POST /api/data-center/sync/reference-data/refresh`
- M2 页面新增“步骤 0”，包含目标日期、零写入预览、二次确认刷新和覆盖证据展示；刷新成功
  后把有效目标交易日带入现有行情任务表单。
- 专项测试 `scripts/smoke_test_data_center_reference_refresh.py` 通过，覆盖零写入、受控写入、
  共同门禁、令牌不可复用、API 和 UI 契约。
- 回归通过：
  - `scripts/smoke_test_stage86_data_center.py`
  - `scripts/smoke_test_stage86_data_center_ui.py`
  - `scripts/smoke_test_stage78_2_incremental_scheduler.py`
  - `node --check web/data_center_stage_c.js`
  - 新增及修改 Python 文件 AST 解析。

## 阻塞原因

- 正式数据写入和外部请求应由用户按人工操作指南执行并核对，本次实现不代替业务操作者
  作出目标日与发布决定。
- 项目统一验证仍会在既有 `smoke_test_a_share_source_database.py` 的
  `raw quality is not passed` 门禁处停止；需要先用本功能和现有行情任务把正式数据补齐，
  再复跑统一验证。

## 潜在风险

- 免费上游可能限流、停服或改变返回结构；参考数据刷新成功不等价于三种行情任务成功。
- 当前参考刷新结果通过页面即时展示，长期证据以规范表来源字段、后续质量报告和发布版本
  成员为准；操作者仍需保存相关 ID。
- 证券目录是当前目录快照，不能替代策略研究所需的点时证券主数据；点时全 A 仍必须使用
  已实现的历史证券主数据与 V7 门禁。
