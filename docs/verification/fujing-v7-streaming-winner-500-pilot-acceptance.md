## 已验证项

- 因子研究主链已由全量 Python 列表改为 SQLite 分阶段流式合同
  `sqlite-batched-v1`：
  - 每 100 只证券计算并幂等写入观察暂存；
  - 股票池日覆盖按批次键幂等累计；

  - 报告按交易日消费，分布统计由 SQLite 单次有序窗口计算；
  - 行业 IC 每次只持有一个行业样本；
  - 制品先有序读取确定哈希，再按 10,000 行分批发布；
  - 发布中状态为 `publishing`，重试时补齐缺行，行数一致后才转为 `ready`。

## 阻塞原因

- 项目统一验证在运行到本轮新增测试前，被既有
  `smoke_test_a_share_source_database.py` 的 `raw quality is not passed` 拦截；
  单独复跑仍可复现。该失败属于 A 股源数据库质量夹具/当前源数据门禁，与本轮
  流式代码路径无调用关系。
- 因统一 runner 遇首错即停止，不能声称“统一正式验证全部通过”；本轮相关验证已
  单独通过。

## 潜在风险

- 全 A 单因子预计约 850 万至 914 万值行，虽然不再持有多份全量 Python 对象，
  仍会产生较长的 SQLite 排序、行业分组和制品发布 I/O。
- 五因子不可并行写入同一 SQLite；正式执行必须串行，并在每个因子后检查空间、WAL、
  行数、哈希和失败恢复点。
- 报告 JSON 仍按交易日保存完整序列；它不再随证券行数线性膨胀，但会随交易日和
  horizon 数量增长。
- 试点库是审计证据，不应被策略运行时误当作正式制品库。

## 发布判断

- 流式因子研究机制：`500 只单 WINNER 试点通过`。
- 旧值兼容性：`334,326 行精确一致`。
- 正式研究库隔离：`通过`。
- 80GB 空间与 WAL 门禁：`通过`。
- 点时全 A 五因子：`尚未授权、尚未执行`。
- 产品或策略有效性：`不能据此发布`；本验收只证明资源机制与数值兼容性。
- 推荐下一步：先修复/解释统一验证的 raw quality 前置失败，再由用户决定是否串行执行
  点时全 A 五因子；即使执行，也不得查看封存样本外或自动激活 V7。
