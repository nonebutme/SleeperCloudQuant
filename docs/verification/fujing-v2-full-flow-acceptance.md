## 2. 策略语义与适配边界

附件原策略是通达信公式语义，核心规则包括：上市超过 200 日；排除 ST、科创板、北交所和 B 股；寻找近期低点买入形态；使用筹码分布条件；按量比分数排序取前 3；次日开盘成交；收盘跌破持仓期最高价 95% 后次日开盘退出。

当前项目没有通达信逐笔筹码分布和未来确认型 `TROUGHBARS/ZIG` 原生数据，因此落库版本采用可执行、无未来函数的适配：

- `WINNER`：以 120 日成交量加权典型价分布近似。
- `TROUGHBARS/ZIG`：以因果的 16 日滚动低点近似。
- 选股强度：`WINNER(H)-WINNER(L) > 30%`。
- 组合排序：按量比原始信号分数降序，每日最多持有 3 只。
- 成交：信号后下一交易日开盘，A 股 T+1、整手、佣金、印花税和滑点均由回测引擎处理。

因此，“拂经v2”是原公式在 SleeperCloudQuant 数据和执行契约上的可回测适配版，不保证与通达信逐日逐票完全一致。

## 5. 发现并处理的问题

| 问题 | 影响 | 处理结果 |
| --- | --- | --- |
| 数据集导入策略时参数丢失 | 示例无法完整进入策略编辑器 | 保留导入草稿及参数 schema，并增加 `execution_price` |
| 数据集深链接被策略工作台初始化覆盖 | 刷新后无法停留在数据集详情 | 初始化时不再覆盖现有 URL |
| 策略运行上下文缺少股票、名称、交易日 | 无法执行板块/ST/上市日过滤 | 单股和组合运行时均注入元数据 |
| 共享组合未绑定策略数据集 | 数据版本与策略引用不可追溯 | 增加数据集解析、执行证据和数据版本绑定 |
| 组合没有按量比取前 3 | 偏离原策略资金分配逻辑 | 使用原始信号分数排序并限制 `max_positions=3` |
| 三种模式不能统一使用次日开盘价 | 成交语义偏离原策略 | 增加 `execution_price=open` 并记录 09:30 成交证据 |
| 独立账户表单分析缺少模式 | 报告可能错误进入组合分支 | 表单任务补齐模式映射 |
| 裸代码 `000001` 被识别为上证指数 | 平安银行组合成交价和净值严重失真 | 只有明确的 `000001.XSHG` 才走指数路由；裸码和 `000001.XSHE` 走股票路由 |
| 报告把卖出日估算胜率当作策略胜率 | 报告显示 73.97%，与引擎 57.65% 冲突 | 优先使用引擎已平仓胜率，并明确口径 |
| 组合报告重复构建同一完成态明细 | 首次打开约 77 秒 | 完成态详情进程内缓存；首次约 38.419 秒，重复打开约 0.450 秒 |
