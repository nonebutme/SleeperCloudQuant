# 参考仓库路由与拼接边界

- `已确认` 本文档服务于当前保守型推进策略。
- `已确认` 本文档只回答“哪些参考仓库承担什么角色、是否进入拆解、是否允许直接拼接”。
- `已确认` 本文档不是逐文件复制清单，不直接触发代码迁移。

## 三、总体结论

- `SleeperCloudQuant-old`
- `TradingAgents-CN-main`

说明：

- 这两个目录在当前方案里承担“可进入后续拆解与拼接评估”的主来源角色。
- 但当前阶段仍然只是能力级拆解，不是立即逐文件复制。

- `rqalpha-master`
- `vnpy-master`

- `backtrader-master`

说明：

- 当前主要用于借鉴轻量回测体验、指标组织方式和示例结构。

## 五、当前阶段允许的“拆解”含义

## 七、发布判断

### 已验证项

- 5 个参考目录在当前方案中的角色已可区分为主拼接来源、语义对齐来源和参考性来源。
- 当前保守型推进下，拆解可以继续，但仍不应跳到逐文件复制阶段。

### 未验证项

- 每个来源仓库的逐文件复用边界
- 每个候选模块的授权结论
- 第一批候选文件的目标落点

### 阻塞原因

- 当前还没有逐文件映射清单
- 当前还没有逐项授权确认结果

### 潜在风险

- 若把“语义对齐来源”误当成“直接拼接来源”，容易造成不必要适配成本
- 若把“参考性来源”误当成“主底座”，容易引入许可和维护风险

### 发布判断

- `已确认` 本文档可作为你确认 5 个参考目录职责边界的直接依据
- `待确认` 逐文件拼接仍应放在下一阶段单独确认
