# A 股受治理增量同步人工操作指南

适用日期：2026-08-19

本流程用于把规范 A 股数据追更到一个已结束的目标日期。系统会把“参考数据刷新”与
`raw`、`qfq`、`hfq` 三种行情任务分开控制；不要跳过预览，也不要并行创建三种价格
口径的任务。

## 1. 启动与进入页面

1. 双击项目根目录的 `启动系统.cmd`。
2. 浏览器打开 `http://127.0.0.1:8010/` 后，进入“数据中心”。
3. 打开左侧 `M1 数据源管理`，选中当前免费上游，执行“逐能力只读探测”。
4. 只有探测结果满足本次所需能力时，才进入 `M2 同步执行器`。

只读探测不会写业务数据。外部接口临时不可用时，应停止本次同步并保留既有已发布
版本，不要反复提交写入任务。

## 2. 步骤 0：刷新发布参考数据

1. 在 `M2 同步执行器` 顶部的“步骤 0”选择目标日期。
2. 点击“零写入预览”。
3. 核对页面显示的交易日历最近日期、目标日前最近开市日、沪深 300 基准最近日期和
   当前证券数量。
4. 预览显示需要刷新时，点击“确认刷新参考数据”，在二次确认框中再次核对目标日期。
5. 等待页面明确显示“参考数据已满足目标日发布门禁”。

该操作只刷新证券目录、A 股交易日历和正式沪深 300 日线基准。它不会启动个股行情
同步。目标日停牌事实会在价格任务启动时刷新；任务完成前，页面中的“交易状态观察”
日期可以仍早于目标日。

预览令牌 15 分钟有效且只能使用一次。修改日期、刷新页面或服务器重启后，都必须
重新预览。

## 3. 串行创建三种行情任务

参考数据通过后，在“创建同步任务”中按以下顺序操作，每次只创建一个任务：

1. 数据集选择 `A股日线行情`。
2. 目标交易日确认已自动带入参考数据刷新后的有效交易日。
3. 同步范围选择“全部当前股票”。
4. 价格口径选择“不复权（raw）”，任务模式选择“快捷追更”。
5. 点击“检查缺口 / 生成区间预览”，核对请求量、路由和分片。
6. 点击“确认创建任务”，等待该任务完成并通过质量与发布门禁。
7. 依次用相同步骤创建“前复权（qfq）”和“后复权（hfq）”任务。

必须按 `raw → qfq → hfq` 串行完成。页面当前一次只接受一个价格口径，这是为了让
每次任务的冻结参数、失败分片、质量报告和发布结果可独立审计。

价格任务会把成功取得规范行情的证券日物化为“正常可交易”状态，并把有界历史区间内
有开市日但三个价格口径均无行情的日期按既有证据规则记录为停牌；这一步用于保持 V7
严格 `trading_status` 数据集逐 bar 可绑定。

## 4. 验收同步结果

对每个任务，打开任务详情并核对：

- 状态为“已发布”或明确的“无需更新”；
- 失败数、隔离数和最后错误；
- 实际写入行数；
- 质量报告 ID；
- 新数据版本 ID；
- 目标交易日与参考数据覆盖一致。
- `security_trading_status_daily` 版本成员的行数、证券数、最早/最晚日期与规范物理表一致，
  且 `sync_run_ref` 指向本次任务。发布器会在落版前自动复核；不一致时任务必须被门禁
  拒绝，不能继续生成发布版本。

三种价格口径完成后：

1. 进入 `M3 质量检查与纠错`，查看是否存在新的阻断或隔离异常。
2. 进入 `M5 快照管理`，核对最新发布版本的成员、截止日期和质量报告。
3. 不要仅因“最新版本已发布”就自动切换默认研究版本。先完成研究复现与业务验收，
   再人工确认是否设为默认版本。

## 5. 失败处理

- 参考数据未满足门禁：不要创建行情任务；先查看上游探测和返回日期。
- 任务部分失败：在任务详情中使用既有失败重试功能，只重试失败/隔离分片。
- 质量门禁失败：到 M3 处理或重拉，不得绕过质量检查直接发布。
- 出现 `release member consistency blocked`：停止后续口径任务，保留错误中的成员差异；
  不得手改版本成员或旧版本，修复物理数据/成员生成逻辑后重新创建任务。
- 免费上游无响应或字段改变：保留旧的 `published` 版本，记录错误，不宣称数据已更新。
- 页面显示的日期或结果不确定：保存任务 ID、质量报告 ID、版本 ID 和错误文本，再停止
  后续步骤。

## 6. 本轮明确不执行的操作

- 不自动把新发布版本设为默认研究版本；
- 不自动运行点时全 A 五因子；
- 不查看封存样本外证据；
- 不激活拂经 V7；
- 不承诺免费上游 SLA、商用或实盘可用性。
